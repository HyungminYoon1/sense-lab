# 시간차 구분 QA inventory

## User-visible claims and controls

- No automatic stimulus; consent checkbox is initially unchecked, start disabled, no history/progress write.
- Explicit start: calibration, orientation, two finite neutral dots, then two answer buttons. No answer before the sequence or duplicate scoring.
- Twelve randomized adaptive rounds: next/result controls, visible score, observed frame/ms feedback, terminal result once.
- Stop, Escape, panel navigation, blur, hidden/page exit: cancel with no answer/result; dots reset; new/reset starts still respect 2s cooldown.
- Bad frame calibration or delay: excluded, no score, deliberate retry.
- New test: reset current session only. Existing three-kind private and shared histories remain unchanged.
- Keyboard and reduced-motion preference: all controls native, no automatic stimulus, no CSS pulse animation.
- Visual checks: idle, shown points, answered and completed; 1440x1000, 390x844 and 320x800; all nav labels, instructions, safety acknowledgment and answer/result controls readable without horizontal clipping.

## Off-happy-path exploration

1. Stop during calibration, repeatedly reset/start and navigate away/back. No queued display or cooldown bypass.
2. Answer early/duplicate; remove consent during playback; simulate delayed rAF in isolated QA context. No score/write from invalid or cancelled frames.

## Evidence boundary

Node pure-model and DOM-double checks are local logic checks. Playwright inputs and rendered captures verify selected Chromium flows/layouts, not human perception, optical display timing, clinical status, physical touch hardware or formal WCAG conformance. Remote CI and public file hashes must be recorded separately after approval.
