### 메인의 정상 UI 캡처·검증 절차

1. `npm run dev -- 0`의 Local 주소를 한 탭에 열고 동일 출처·포트를 유지합니다. 시작 화면에서는 저장 기록과 갤러리 요약이 새로 생기지 않아야 합니다. 배포 preview는 저장 데이터와 갤러리가 같은 출처인지 확인합니다.
2. 색감: 보이는 다른 색 칸을 고르고 `다음 색`을 누릅니다. 틀려도 정답 공개 후 진행할 수 있습니다. 12번째 답안 뒤 `결과 보기`를 누르면 실제 결과와 색감 기록 카드가 생깁니다. 아래 `색감 기록`으로 내려가 최신 카드를 펼쳐 단계·ΔL·정오답을 함께 캡처합니다. 새 테스트를 한 번 더 마치면 최근 변화가 표시됩니다. 화면 색을 구분하기 어려워 오답이 있어도 그 실제 기록을 캡처하고 점수를 주입하지 않습니다.
3. 반응: `반응속도` → 큰 `시작하기` 영역 클릭/터치/Space/Enter → 손/키를 놓고 무작위 신호 대기 → `지금!`에서 한 번 반응 → 250 ms 확인 종료까지 기다림 → `다음 시도` → 다시 시작합니다. 정상 5회 완료 뒤 아래 기록 카드를 펼쳐 중앙값·MAD·범위 및 실제 각 시도를 캡처합니다. 신호 전 입력은 실패하고, 실패 상태의 연타는 기록을 만들지 않아야 합니다. 대기/확인 중 다른 버튼 입력은 제외될 수 있으니 기록 삭제 QA는 시도 종료 후 수행합니다.
4. 기억: `위치 순서 기억` → 필요하면 `천천히` 선택 → `순서 보기` → 표시되는 번호를 관찰 → 입력 안내 후 같은 순서의 칸 선택 → `다음 순서 보기`. 8라운드 종료 뒤 기록을 펼쳐 순서 길이별 정오답·속도를 캡처합니다. 표시 중 탭을 바꾸거나 창의 포커스를 잃으면 그 순서는 취소되므로 한 탭 안에서 진행합니다. 다른 속도의 기록은 최근 비교에 섞이지 않아야 합니다.
5. 같은 URL을 새로고침하고 기록이 남는지 확인합니다. 카드의 `이 기록 삭제`로 해당 기록만 제거한 뒤 남은 기록과 완료 종류 수 감소를 확인합니다. 페이지 아래 `전체 기록 삭제`로 sense-lab 기록과 자기 summary만 사라지는지 확인합니다. 다른 앱 항목은 유지해야 합니다. `새 테스트`가 기록 삭제와 혼동되지 않는지 확인합니다.
6. 320/390 px에서 기록 카드를 펼친 상태, 삭제 버튼, 테스트 선택, 새 테스트, 키보드 Tab·Space·Enter 경로를 확인합니다. 새 기록/빈 상태/손상/저장 실패는 구분해서 기록합니다. 고주파는 명시적 듣기 버튼 전에는 소리가 나지 않아야 하며 실제 청취 대신 음량 0으로 재생·중단 경로만 QA할 수 있습니다.
